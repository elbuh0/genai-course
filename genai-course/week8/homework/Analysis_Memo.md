Dataset Design and Compiler ReAct Agent: Failure Mode Diagnostic Memo

Evaluation results appeared initially promising for task success (1.00), step efficiency (0.91), and hallucination (0). However, a closer review revealed two hallucinations, lowering task success to 0.95 and raising the hallucination count to 2. First, in T3, the model made a claim that no tool output supports, specifically answering that it had found “seen drone videos” despite its searches dropping the word “drone”, thereby returning videos not confirmed to be drone footage. Second, in T10, the model hallucinated a tool input made up of a repeated Unicode escape code, likely imitating Cyrillic military vehicle search terms that json.dumps had by default returned to it as escape codes.

The two failure modes most likely to cause problems in production for this domain are therefore tool-input hallucination, which can result in methodologically unsound data-split design, and cascading failure, which results in the retrieval of unusable data, e.g., irrelevant images, as when the agent in a previous run accepted 40 irrelevant images, including images showing cages on a church tower, as valid caged surface-to-air missile launchers. Addressing these failure modes is critical to the domain of dataset design and compilation, as methodologically unsound dataset design and insufficient data quality would undermine research success.

I would make the following two architectural changes prior to deploying: (1) Hardening tool boundaries, e.g. returning tool outputs as readable text and capping tool inputs such as T10’s malformed repeated escape-code query; and (2) LLM-as-judge to catch irrelevant tool output post-initial answer (“Münster, St.-Lamberti-Kirche, Turm -- 2017 -- 2088.jpg”) that would otherwise result in a cascading failure. These changes would specifically address the current implementation’s malformed tool inputs and post-initial answer acceptance of irrelevant images hampering effective data compilation.

Two new tools would equally improve task success rate. The first is an expanded data-acquisition tool that would extend the agent’s search past Wikimedia Commons to additional publicly accessible sources, such as Telegram and YouTube, which are superior repositories of current battlefield drone video and photography of caged and unmodified armored vehicles from active conflicts. The second is an image-pixel inspector to flag potentially irrelevant data prior to data output, automatically re-querying any class with results below a user-specified quality threshold. The current implementation outputs a dataset that must be manually inspected post-download, which in prior and current implementations included multiple irrelevant images, such as a person named Sam (matching the acronym SAM, for surface-to-air missile) and the interior of a surface-to-air missile system, irrelevant to exterior vehicle recognition. 

I recommend the deployment of this implementation with the above-noted architectural changes and at least the first of the two suggested tool additions. I also recommend proceeding as a pilot with human subject-matter expert (SME) review in order to ensure not only adequate data collection but also methodologically sound data-split design.
